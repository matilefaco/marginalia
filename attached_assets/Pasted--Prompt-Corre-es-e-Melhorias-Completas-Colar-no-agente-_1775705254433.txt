## 4. POSTS SEM REFERÊNCIA — Corrigir exibição do tipo no feed

### Problema

Posts do tipo `postType: "THOUGHT"` ainda aparecem no feed com o label do tipo (INSIGHT, REAÇÃO, etc.) mesmo quando não têm categoria definida. Isso precisa parar.

### Correção no componente MarginCard

No header do card, usar a seguinte lógica:

```typescript
// Determinar o que mostrar no header
const effectivePostType = margin.postType ?? (margin.excerpt ? "EXCERPT" : "THOUGHT");

const headerLabel = effectivePostType === "THOUGHT"
  ? "PENSAMENTO"  // sempre, independente de ter tone ou não
  : margin.type;  // INSIGHT, REAÇÃO, TEORIA, DESTAQUE — só para EXCERPT

const headerIcon = effectivePostType === "THOUGHT"
  ? "✏️"
  : getTypeIcon(margin.type); // função já existente
```

Ou seja: todo post THOUGHT mostra `✏️ PENSAMENTO` — nunca INSIGHT, nunca REAÇÃO, nunca TEORIA. O campo `tone` (noturno, intenso, etc.) aparece ao lado se existir, mas o label principal é sempre PENSAMENTO.

Aplicar essa correção em todos os lugares onde o tipo do post é exibido: feed home, explorar, perfil, thread.

## 8. NAVEGAÇÃO — Corrigir redirecionamento errado ao clicar em posts

### Problema

Ao clicar em um post no feed, o app redireciona para um post diferente do clicado.

### Causa provável

O `onClick` do card está usando um índice do array em vez do `id` do post, ou há um mapeamento incorreto entre a lista renderizada e os dados.

### Correção

No componente `MarginCard` e em todos os lugares onde o card é clicável, verificar que o handler de navegação usa o `id` do próprio post:

```typescript
// ERRADO — usar índice ou variável de closure errada:
onClick={() => navigate(`/thread/${margins[index].id}`)}

// CORRETO — usar o id do próprio objeto:
onClick={() => navigate(`/thread/${margin.id}`)}
```

Procurar por todos os usos de `navigate('/thread/')` no código e garantir que o ID passado corresponde ao post que está sendo renderizado naquele momento. Verificar especialmente listas com `.map()` onde o parâmetro pode estar sendo capturado incorretamente no closure.

Testar: clicar em cada post do feed deve abrir o thread daquele post específico, não de outro.

## 9. PRIMEIRO ACESSO — Redirecionar para Home, não para post aleatório

### Problema

Quando um novo usuário cria conta e entra no app pela primeira vez, é direcionado para um post aleatório em vez da tela Home.

### Correção no fluxo de auth

No `AuthContext.tsx` ou no componente que controla o redirecionamento pós-login/cadastro:

```typescript
// Após signUp bem-sucedido e conclusão do onboarding:
navigate("/", { replace: true });
// O replace: true garante que o usuário não volta para o onboarding
// ao pressionar o botão de voltar

// Após signIn:
navigate("/", { replace: true });
```

Verificar também se há algum `useEffect` que detecta a sessão Supabase e redireciona para uma rota que não seja `/`. Se houver, garantir que o redirecionamento padrão seja sempre para `/` (HomeScreen).

Adicionalmente, garantir que ao completar o onboarding (último passo de seleção de livros), o redirect final seja:

```typescript
navigate("/", { replace: true });
```
